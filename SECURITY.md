## Backup and restore (operators)

`DATA_DIR` is the complete persistent state. Back it up with the server stopped:

```sh
docker compose stop chatui
docker compose run --rm chatui node server/cli.ts backup /data-backups/2026-09-30
docker compose start chatui
```

- `backup` first runs the server's startup recovery (finishing operations, generation checkpoints, memory intents and pending removals, and rolling back unfinished imports). It then copies everything except derived indexes (`<user>/index/`), `import-staging/`, sessions (add `--include-sessions` to keep people signed in) and the lock, writes `manifest.json` with every file's SHA-256, and re-verifies the copy.
- **A backup contains secrets** (`_system/providers.json` API keys) and all user content. Store and transfer it privately.
- `restore <dir>` works only into an **empty** `DATA_DIR`. It verifies every checksum, refuses missing, altered, unlisted, linked or out-of-tree files, copies with private permissions, then runs startup recovery (which rebuilds the indexes). A failed restore leaves the directory empty.
- A filesystem snapshot of a running server is also consistent enough to restore: recovery finishes whatever was in flight (tested).
- Both commands refuse while a live server holds `DATA_DIR`.

## Exceptions

| Requirement                                        | Why unresolved                                                         | Risk                                                               | Compensating control                                                  | Plan                                             |
| -------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------- | ------------------------------------------------ |
| Rate limits and the instance lock are per process  | Distributed limiting is out of scope; the deployment is single-process | A second process on the same `DATA_DIR` would have its own budgets | The instance lock refuses a second server; Compose runs one replica   | None unless multi-process deployment is designed |
| Screen-reader and cross-browser security UI checks | Only Chromium is automated here                                        | Browser-specific differences go unnoticed                          | Standards-based markup; axe scans                                     | Add Firefox/WebKit to CI in Phase 17             |
| Stale-lock detection uses process ids              | A pid reused by an unrelated process after a crash looks live          | `backup`/`restore` refuse until the lock file is removed           | Clear message naming the pid; the lock lives in `_system/server.lock` | Documented; operators delete the stale file      |
| `\cancelto` in math renders without its arrow mask | The mask is a `data:` URL, which `img-src` forbids                     | Cosmetic                                                           | —                                                                     | None (the CSP wins)                              |
