# Security review (Phase 16)

This is the security review of everything built through Phase 15. Each control names the code that implements it and the test that proves it; unresolved findings are listed under [Exceptions](#exceptions). Re-run the review when a phase adds a route, a store, a renderer or a dependency.

**Reporting a problem:** open a private security advisory on the repository, or contact the maintainer directly. Please don't file a public issue for a vulnerability.

## Threat model in one paragraph

ChatUI is a self-hosted, multi-user chat front end for llama.cpp. Its users are trusted to use their own accounts but not anyone else's. Admins are trusted with instance settings and provider secrets. The model and everything it reads (files, pasted pages, earlier chats, tool results) are **untrusted output**: a reply may be crafted to attack the user who reads it. The network between the browser and ChatUI is trusted only behind TLS (`https` `PUBLIC_ORIGIN`). Provider endpoints are reached server-side only, through an SSRF policy. A single ChatUI process owns `DATA_DIR`.

## Review

| **Sessions**                                        | Opaque random tokens; only the SHA-256 is stored (`server/auth/sessions.ts`). Sessions rotate on login (fixation). Absolute and idle expiry. Disabling, deleting, a role change, a password change and an admin reset revoke sessions, checked on every request from the fresh user record (INV-17). Cookie flags per origin: `HttpOnly`, `SameSite=Lax`, `__Host-` and `Secure` on https; `X-Forwarded-Proto` is never trusted.                                                                                                                    | `tests/server/auth.test.ts` (fixation, expiry, INV-17, password change, cookie flags, token hash at rest), `tests/server/admin.test.ts` (reset revokes)                                                                                                                                              |
| **Authorization**                                   | Route policies `public`/`user`/`admin` in the registry (`server/registry.ts`); identity only from the session (INV-14). Ownership lives at the storage/service boundary: every store takes the owner's id and builds paths from it, so another user's id finds nothing. **New:** `AdminService` re-reads the actor's account on every operation and requires an active admin, whatever the caller claims.                                                                                                                                           | `tests/server/security.test.ts` (services called directly with a mismatched user id; a forged admin context; a disabled admin), `tests/server/auth.test.ts` (another user's data looks missing), `tests/server/attachments.test.ts` (INV-15)                                                         |
| **CSRF**                                            | Synchronizer token plus `X-Expected-User` on every `csrf: "token"` route, including multipart uploads and imports. Same-origin check on login and registration. The client refetches the token and retries exactly once, only after `CSRF_INVALID`.                                                                                                                                                                                                                                                                                                 | `tests/server/registry.test.ts` (INV-16, enumerated over every state-changing route), `tests/client/api.test.ts` (one retry)                                                                                                                                                                         |
| **Routing / SSR boundary** (INV-53, INV-54, INV-57) | `/api/*` never reaches the document handler; missing assets are non-HTML 404s. Documents resolve the session server-side before rendering, and loaders use the same owner-checked services as the API. Protected HTML is `private, no-store`. A per-request QueryClient with a dehydrate allowlist. **New:** an undecodable document path is a plain 400, before the framework router.                                                                                                                                                              | `tests/server/boundary.test.ts`, `scripts/verify.ts` (INV-54/55/57, two users' concurrent documents, `/admin` gated by the server-side role), `tests/server/security.test.ts`, `tests/e2e/security.spec.ts` (malformed and hostile URLs; a `</script>` title in the document and its bootstrap data) |
| **Validation** (INV-02)                             | Every route has strict params, query and body schemas; unknown fields are rejected. JSON bodies are capped (`JSON_BODY_LIMIT`). **New:** a malformed percent-encoding in a path parameter is `VALIDATION`, not `INTERNAL`.                                                                                                                                                                                                                                                                                                                          | `tests/server/errors.test.ts`; `tests/server/security.test.ts` (an unknown body field and an unknown query parameter, enumerated over every route)                                                                                                                                                   |
| **DTOs** (INV-03)                                   | The registry parses every handler result through the route's explicit response schema before writing it. **New lint rule** (`eslint.route-inventory.js` `dtoRestriction`): only the registry and the error contract may call `res.json()`.                                                                                                                                                                                                                                                                                                          | `tests/server/registry.test.ts` (every fixture answers with its DTO; the lint rule), `tests/server/auth.test.ts` and `tests/server/providers.test.ts` (no hashes, keys or base URLs in any response)                                                                                                 |
| **SSRF** (INV-19)                                   | Provider URLs must be http(s) without credentials. Every resolved address is checked at request time and the connection is pinned to the checked address (DNS rebinding). Redirects are never followed. Metadata and link-local ranges are denied; exceptions are exact host/address/port tuples. The same guarded client serves admin create, edit and "Test".                                                                                                                                                                                     | `tests/server/providers.test.ts` (rebinding, redirects, metadata, allowlist), `tests/server/admin.test.ts` (SSRF on create, edit and test)                                                                                                                                                           |
| **Model validation** (INV-18, INV-44)               | Every send and regeneration resolves the provider/model pair on the server. Hidden models are admin-only. Images and audio need the model's modality. `think` is ignored for models without reasoning.                                                                                                                                                                                                                                                                                                                                              | `tests/server/providers.test.ts`, `tests/server/admin.test.ts` (hidden models), `tests/server/attachments.test.ts` (INV-44), `tests/server/think.test.ts`                                                                                                                                            |
| **Filesystem** (INV-12, INV-28)                     | All request-influenced paths come from `DataPaths` (`server/storage/paths.ts`): UUID, hex or `YYYY-MM` components only, resolved inside `DATA_DIR`. **New:** the artifact, import-staging and temporary-chat paths moved into `DataPaths`, so no store builds its own path from an id. Import journals only touch paths under the importing user's directory.                                                                                                                                                                                       | `tests/server/security.test.ts` (hostile components across every path constructor), `tests/server/attachments.test.ts` (hostile filenames), `tests/server/portability.test.ts` (archive traversal, links, absolute paths)                                                                            |
| **Uploads** (INV-27)                                | Types are decided by content sniffing (spoofed extensions and types, SVG, HTML and invalid UTF-8 are refused). The size limit is enforced while streaming. Pixel limit (`MAX_IMAGE_PIXELS`), quota with reservations, concurrent upload cap. Served with the sniffed type, `nosniff`, a `sandbox` CSP and private caching; only raster images are inline.                                                                                                                                                                                           | `tests/server/attachments.test.ts`, `tests/server/profile.test.ts`, `scripts/verify.ts`                                                                                                                                                                                                              |
| **Captured files** (INV-41)                         | Captured files are always served as `text/plain` with `nosniff` and a sandbox CSP, and shown as source, never rendered.                                                                                                                                                                                                                                                                                                                                                                                                                             | `tests/server/artifacts.test.ts`, `tests/e2e/source-artifacts.spec.ts`                                                                                                                                                                                                                               |
| **Imports and exports** (INV-50)                    | Archives are ZIP32 read with entry, size, ratio and time limits; checksums are verified; unknown files, links and traversal are refused before staging. Imports are owner-only, journaled, and rolled back on a crash.                                                                                                                                                                                                                                                                                                                              | `tests/server/portability.test.ts` (bombs, traversal, checksums, ownership, rollback)                                                                                                                                                                                                                |
| **Memories and proposals** (INV-38)                 | Suggestions are only recorded; a change needs the user's acceptance, which checks the reply's snapshot hashes (a stale accept conflicts) and is per-user.                                                                                                                                                                                                                                                                                                                                                                                           | `tests/server/memories.test.ts` (acceptance, stale snapshot, update/forget scope, ownership)                                                                                                                                                                                                         |
| **Rendering** (INV-22, INV-45)                      | Markdown without raw HTML, URLs filtered by `safeUrl`, highlight.js and KaTeX output inert, interactive blocks parsed never evaluated (`docs/threat-model-14b.md`). Rich paste reads clipboard HTML in an inert DOMParser document.                                                                                                                                                                                                                                                                                                                 | `tests/client/*` (XSS payloads), `tests/client/ui-blocks.test.tsx`, `tests/client/composer-extras.test.tsx`, `scripts/verify.ts` (chat demo: no console errors or CSP violations)                                                                                                                    |
| **Rate limits**                                     | Sign-in: 10 per 15 min per address and per username, plus the password-hashing queue cap. **New:** per-account limits declared on each route (`rateLimit`), counted after authentication and CSRF: generation starts, uploads/imports/full exports, admin changes → `429 RATE_LIMITED` with `Retry-After`. **Limits are per process** (no distributed limiting; single-process deployment).                                                                                                                                                         | `tests/server/auth.test.ts` (login, hashing queue), `tests/server/security.test.ts` (declarations enumerated; limits per account; rejected requests cost nothing)                                                                                                                                    |
| **Resource limits** (INV-62)                        | Generation admission globally, per provider and per user. SSE observers per user and in total, with lagging observers dropped. Upload reservations and concurrency. JSON body cap; multipart size checked while streaming; import time limit. **New** (`server/http-server.ts`): 16 KB request headers (431), 30 s to send them, `REQUEST_TIMEOUT_MS` per request, `MAX_CONNECTIONS`.                                                                                                                                                               | `tests/server/auth.test.ts`, `tests/server/streaming.test.ts`, `tests/server/attachments.test.ts`, `tests/server/security.test.ts` (431, limits applied)                                                                                                                                             |
| **Headers / CSP** (INV-57)                          | Helmet: strict CSP with a fresh 128-bit nonce per response used by every script and the theme bootstrap; no `unsafe-inline`/`unsafe-eval` in production; `object-src`, `frame-src`, `worker-src` and `base-uri` are `'none'`; `frame-ancestors 'none'`. Also `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `nosniff`, COOP and CORP `same-origin`. Development relaxes only styles and the HMR websocket. **New:** a `Permissions-Policy` that allows only the microphone (dictation), clipboard writes and full screen for this origin. | `tests/server/csp.test.ts`, `tests/server/security.test.ts` (the same headers on HTML, JSON, attachment bytes and errors), `scripts/verify.ts` (nonce on every script, no CSP violations)                                                                                                            |
| **Performance hints and prefetch** (INV-31)         | Hint cookies are validated and never carry identity. Prefetch uses the same user-scoped query keys, authenticated fetch and CSRF rules; the cache is purged on account switch.                                                                                                                                                                                                                                                                                                                                                                      | `tests/client/prefetch.test.ts`, `tests/client/*` (account switch purges, user-scoped keys)                                                                                                                                                                                                          |
| **Telemetry privacy**                               | Performance marks carry only names and generation ids.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `tests/e2e/security.spec.ts` (sentinel message text, file name, username, CSRF token and cookies never in marks, measures or the diagnostics summary)                                                                                                                                                |
| **First-party runtime**                             | All JS, CSS, fonts and icons are served from the app origin; no service worker; providers are contacted server-side only.                                                                                                                                                                                                                                                                                                                                                                                                                           | `scripts/verify.ts`, `tests/e2e/security.spec.ts`                                                                                                                                                                                                                                                    |
| **Error leakage** (INV-01)                          | Contract errors carry only safe messages; anything else is `INTERNAL` without internals; upstream bodies are never forwarded.                                                                                                                                                                                                                                                                                                                                                                                                                       | `tests/server/errors.test.ts`; `tests/server/security.test.ts` (over 300 malformed requests across every route: no 500, stack, path or upstream text)                                                                                                                                                |
| **Logs**                                            | Pino redaction of secret-like fields. Request logs omit headers, cookies and query strings; message text and file contents are never logged.                                                                                                                                                                                                                                                                                                                                                                                                        | `tests/server/logger.test.ts`, `tests/server/admin.test.ts` (secret sweep), `tests/server/security.test.ts` (sentinel password, CSRF token, cookie, message text, file name and memory never in default-level logs)                                                                                  |

## Dependencies

- `npm audit --omit=dev` (production tree): **0 vulnerabilities** on 2026-10-30. CI runs `npm audit --audit-level=high` on every push.
- **Update policy:** releases are adopted once they are at least 14 days old, unless they fix an advisory that affects ChatUI. Patched in this phase: `react` / `react-dom` 19.3.1, `express` 5.3.0, `pino` 10.4.0.
- Newer releases not yet adopted, because they are under 14 days old: `react-router` 8.5.1, `@tanstack/react-query` 5.105.0, `katex` 0.19.1, `lucide-react` 1.65.0. Major upgrades (`typescript` 7, `@types/node` 26) are out of scope.

## Exceptions

| #   | Requirement                                             | Why unresolved                                                            | Risk                                                                                         | Compensating control                                                                                                                                         | Plan                                                          |
| --- | ------------------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| E1  | Distributed rate limiting                               | Out of scope: ChatUI is a single process per `DATA_DIR`.                  | Counters reset on restart, so an attacker who can restart the server gets a fresh allowance. | Restarting needs host access; sign-in limits and the hashing queue still apply.                                                                              | None while single-process.                                    |
| E2  | Cross-browser screen-reader verification                | No automated screen-reader runner in CI.                                  | Assistive-technology regressions could go unnoticed.                                         | Accessibility-tree snapshots and axe checks (Phase 15).                                                                                                      | Manual NVDA/VoiceOver pass in Phase 18.                       |
| E3  | Malware scanning of uploads                             | ChatUI does not scan files.                                               | A user could store malware in their own files.                                               | Content sniffing, no executable types, `nosniff` and a sandbox CSP on every download; files are private to their owner.                                      | Documented in the README; operators can scan `DATA_DIR`.      |
| E4  | `chat_template_kwargs` (Think) against a live llama.cpp | No live server was reachable.                                             | The request may be rejected by an older server.                                              | Sent only for providers marked `reasoning: true`; a rejection is a normal provider error.                                                                    | Verify with `scripts/probe-provider.ts` on the next live run. |
| E5  | Online (hot) backup                                     | A consistent copy needs either a stopped server or a filesystem snapshot. | Copying a running `DATA_DIR` by hand may capture half-finished multi-file writes.            | The CLI refuses while the server runs; the README documents snapshots; startup recovery repairs interrupted states.                                          | None planned.                                                 |
| E6  | HSTS                                                    | ChatUI does not terminate TLS.                                            | A first visit over http could be downgraded.                                                 | Production LAN access requires an https `PUBLIC_ORIGIN` behind a TLS proxy, and plain-http non-loopback origins are refused at start. Set HSTS on the proxy. | Documented in the README (TLS proxy section).                 |
