# ChatUI rebuild roadmap (from Phase 7)

Inputs: the phase package (v5.3.2, treated as partly outdated), `ChatUI_rebuild_plan.md`, and the old build's feature list (`ffe33be` … `e0c81d4`).
State: see §5 Progress.

## 1. What was wrong with the old order

- **Storage changed late.** `e85ff4a` switched to username/title paths and format v2 after nearly every feature had been built on v1, so a migration path had to be added. **Fix:** storage stays frozen (UUID paths, format v1, already built).
- **Visuals were redone 6+ times** (`44c97e5`, `360c885`, `ba581c4`, `b2407ef`, `e23861c`, …). **Fix:** the measured tokens and an automated measurement audit go in at the first UI gate (7a), and every later gate must keep the audit green.
- **The phone layout was patched in 5 separate commits** after the features were built. **Fix:** Mobile moves up to just after loading (before admin, uploads and the rest), so every later feature is built and tested at phone size from the start.
- **The tool loop came before memory, and memory was built on it.** The package defines memory tools only. **Fix:** decide whether general tools exist _before_ 13b, so 13b builds the tool loop once (see decision D2).
- **Highlighting, table tools and math were scattered** across 4 commits, and the perf budget was set before or around them. **Fix:** the response rendering gate moves before perf, so `performance-budget.json` is set with the lazy renderers already in place.
- **Library, profile photos and search tabs existed before the things they list.** **Fix:** they come after uploads (12), and search tabs come after Library.
- **Demo data came late** (`9fe5687`). **Fix:** it moves to 7b, so every UI gate after it has seeded chats for screenshots and audits.

## 4. Decisions (settled 2026-10-29)

- **D1 Storage paths: keep** `data/<user-uuid>/chats/<conversation-uuid>.md`, format v1, as built. The old username/title layout (`e85ff4a`) conflicts with contracts §1 and INV-12 and would force format v2 plus a migration.
- **D2 General tools: yes.** Before 13b, amend contracts §4.3 and the stored format so memory proposals and the general tools (`search_chats`, `read_chat`, `list_files`, `read_file`, `get_current_time`, `calculate`, `create_file`, with tool chips on saved replies) share one tool loop, built once.
- **D3 Intelligent UI (14b)** still needs its own threat model before it is built: an interpreter, no `eval`, a bounded runtime, no network access.
- **D4 `/` opens the chat** (`/chat/new` or `/login`); the status page is `/status`. Done in 7a.
- **Accent: orange** (plan §7 option: `#f26b1d` light, `#c85512` dark) instead of blue. Done in 7a.
- **Workflow:** commits go straight to `main`.

## 6. Phase 7a plan (as approved)

**Routes** (`app/routes.ts`): a pathless protected `_app` layout that owns the shell, the draft and generation observation, with `chat/new`, `chat/:conversationId`, `settings/*` and `admin` (overlay placeholders until 7b), plus `*`. `/chat` and `/chat?c=<id>` redirect to the new paths. Path builders live in `app/lib/paths.ts`. Overlays keep the background conversation through `location.state`.

**Query** (`app/lib/query/`):

- `keys.ts`: user-scoped key factory (`["u", userId, …]`).
- `client.ts`: browser QueryClient (a fresh one per document request on the server).
- `ssr.ts`: dehydration allowlist for session, conversation list, active conversation and models.
- Loaders prefetch the bounded critical set into a request QueryClient and return `dehydrate()`. `clientLoader` skips the server loader after hydration, so there is no second loader cache.
- `apiFetch` stays the only adapter.
- Account change runs `queryClient.clear()`.

**Primitives** (decision record in `ARCHITECTURE.md`):

| Control                            | Choice                         |
| ---------------------------------- | ------------------------------ |
| Menus (row, profile, conversation) | Radix DropdownMenu             |
| Model picker                       | Radix DropdownMenu radio group |
| Confirm                            | Radix AlertDialog              |
| Rename and overlays                | Radix Dialog                   |
| Tooltips                           | Radix Tooltip                  |
| Desktop sidebar collapse           | Native                         |
| Toasts                             | Native live region             |
| Composer                           | Native textarea                |

**Components** (`app/chat/…`): Shell, Sidebar, ConversationList, ProfileMenu, Header, ModelPicker, Transcript, Message (memoized), LiveReply, Markdown (react-markdown + remark-gfm, no raw HTML, `urlTransform` that strips `javascript:`, `data:` and `vbscript:`), CodeBlock (copy), Composer, ScrollToLatest, `useScrollIntent`, Toasts, ConfirmDialog.

**Styles:** `app/styles/tokens.css` (§5–7 values, light and dark), plus CSS split by area.

**Server changes:** none beyond the document routes, a `sidebar` cookie read in the root loader, and `safeReturnTo` accepting the new paths.
