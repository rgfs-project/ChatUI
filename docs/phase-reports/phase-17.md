## Phase 17 report

- **Plan:**
  - Package 17: an invariant audit first. For every invariant INV-01 to INV-62 except INV-51 (Phase 19), break its enforcement on purpose and show that the tests the register names fail.
  - Then complete the coverage the spec lists, add a clean-checkout proof and its CI job, and run the gates repeatedly.
  - Bug fixes needed to pass are in scope and listed below.

- **Invariant audit:**
  - `scripts/invariant-audit.ts` with `scripts/invariant-mutations.ts`, run as `npm run audit:invariants`. Each mutation is the smallest edit that defeats one invariant's enforcement. The script applies it, runs the named Vitest files, Playwright specs or `verify` (rebuilding first where needed), and always restores the files. Each check has a 10-minute limit.
  - **Result: 61 of 61 mutations killed** (table in `docs/invariant-audit.md`, generated by the script).
  - The first runs left **11 survivors**. Each was a real gap, a duplicated guard, or a bug:

- **Clean-checkout proof** (`scripts/clean-checkout.ts`, `npm run clean-checkout`, new CI job "Clean-checkout proof"):
  - It runs a fresh clone, `npm ci`, writes `.env` from `.env.example`, builds, and creates an admin via the CLI with the password on stdin.
  - It then starts the server and, in a real browser, signs in, sends, sees the streamed reply, reloads, and checks the console stays clean.
  - Finally it shuts down cleanly and deletes `data/` except `.gitkeep`; the old account no longer exists and the app starts fresh. The working tree stays unchanged.
  - Result: **15/15 checks**.
- **Coverage added:**
  - `tests/e2e/reliability.spec.ts`:
    - a provider failure ends as one failed reply without upstream details, and the next send works;
    - two users stream at the same time in separate browsers; neither sees the other's text, and the other's chat URL is a 404;
    - a SIGKILL mid-reply on a server of its own comes back as one interrupted reply with its checkpointed text.
  - Unit and integration tests for the gaps above.
  - The other spec items were already covered by earlier phases' tests: Markdown round trips (examples plus fast-check), the index, locking, atomic writes, provider errors, the state machine, races, sniffing, auth, isolation, streaming replay/resync, recovery, admin, routing, SSR/hydration, prefetch, lazy chunks, the 200-message transcript, composer IME and double send, nested dialogs and first-party runtime.
- **Fixes found while doing this:**
  - **INV-61 late writers** (above).
  - The E2E server ran with production rate limits, so the suite tripped the 30 generations/minute limit (fixed in a commit before this phase) and the 10 sign-ins per 15 minutes per address. The sign-in limit is now configurable (`RATE_LIMIT_LOGIN`, default 10) and high in the E2E server only; its behaviour stays tested in `tests/server/auth.test.ts`.
  - The E2E mock provider now reports 4 slots, so two users can stream at once. Without a slot count the mock is treated as router mode with one slot.
